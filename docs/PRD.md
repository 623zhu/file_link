# 文件链接管理器 PRD

**产品暂定名：** File Link  
**文档类型：** 产品需求文档（PRD）  
**版本：** 0.2  
**状态：** 草案  
**日期：** 2026-11-05

---

## 1. 背景与问题

计算机文件管理默认是树状目录：磁盘 → 文件夹 → 子文件夹 → 文件。文件一旦变多、变散，真正常用、真正重要的那一小批就会被埋掉。找一个 HTML、一份报告、一个脚本，往往要一层层进目录。

现有方案都没有对准这个问题：

| 类型 | 例子 | 为什么不够 |
| --- | --- | --- |
| 系统文件管理器 | 资源管理器 | 管整棵树，不是「重要文件」 |
| 桌面整理 | Fences、DeskBox | 管的是桌面图标，不是文件链接层 |
| 启动器 | Flow Launcher | 全盘搜索，不是一份可维护的重要清单 |
| 标签/资料库 | TagSpaces、DAM | 仍以文件夹或整库为中心 |

**真正要管的不是文件，而是文件的 link。** 文件继续待在原路径，软件只维护一层引用：哪些重要、怎么分组、从哪打开。删的是 link，不是文件。

HTML 只是第一类被管理对象，用来把模型做清楚。

---

## 2. 产品定位

File Link 是一层 **本地文件链接管理器**。

- 不是资源管理器，不负责复制、移动、删除原文件
- 不是桌面整理工具，不接管 Windows 桌面
- 不是全盘搜索启动器
- 是一份用户亲自维护的「重要文件链接集合」：点名收录，或绑定文件夹按规则生成链接，集合可随新文件更新

一句话：**磁盘管文件在哪；File Link 管我要常用哪些。**

---

## 3. 目标与非目标

### 3.1 目标

1. 让用户只管理自己指定的重要文件链接，而不必面对整棵目录树。
2. 通过绑定文件夹并按类型规则生成链接。
3. 绑定文件夹后，新出现的符合规则的文件，可自动生成链接，或由用户手动扫描导入。
4. 打开链接即用系统默认方式打开原文件；从本产品移除只删除链接。
5. 产品模型可扩展到 HTML 以外的文件类型，但首期以 HTML 把主流程跑通。

### 3.2 非目标（首期不做）

- 替换资源管理器，或提供完整的复制/剪切/重命名/权限管理
- 整理、分区、美化 Windows 桌面
- 全盘索引、全文检索、重复文件清理
- 云同步、多设备账号、协作共享
- 把文件吸入产品自己的库（拷贝入库）
- 标签图谱、AI 自动分类等复杂组织系统

---

## 4. 核心概念

| 概念 | 含义 |
| --- | --- |
| 原文件 | 磁盘上真实存在的文件，产品不移动、不复制、不删除它 |
| Link | 指向原文件的一条引用（路径 + 显示名 + 来源 + 分组等元数据） |
| 文件夹绑定 | 用户指定一个目录作为链接来源 |
| 规则 | 绑定后收录哪些文件，首期默认 `*.html` / `*.htm` |
| 自动导入 | 监视绑定目录，符合规则的新文件自动建 link |
| 手动扫描 | 用户点击后，扫描绑定目录，为尚未建 link 的新文件建 link |
| 集合 | 用户看到的全部 link，可按来源/分组浏览，不是磁盘树 |

---

## 5. 用户与场景

**用户：** 本机有大量散落文件（尤其 HTML 工具页、报告、脚本等），只关心其中一部分，不想为它们改目录结构，也不想把桌面堆满快捷方式。

**场景：**

1. 某个文件夹专门放 HTML 工具，以后还会往里丢新的 → 绑定该文件夹，现有 HTML 全部生成链接。
2. 过几天文件夹里多了新 HTML → 自动出现在集合里，或点「扫描新文件」再导入。
3. 某个文件不再重要 → 从 File Link 去掉链接，磁盘上的文件还在。

## 6. 功能需求

### 6.1 手动导入链接

当前版本不提供。收录只通过绑定文件夹。已有仅手动来源的链接仍留在数据文件中，但界面不再展示。

### 6.2 绑定文件夹

- 通过系统文件夹选择框绑定一个目录。
- 绑定后立即按规则扫描（首期 HTML，可选是否包含子文件夹）。
- 为命中的每个文件创建 link：来源=`文件夹`，并记录所属绑定。
- 同一目录不可重复绑定。
- 解除绑定：删除该目录自动生成的 link。原文件一律不动。

### 6.3 新文件进入绑定目录

- 每个绑定可开关 **自动导入**。
  - 开：监视目录（及可选子目录），新文件符合规则则自动建 link，并提示数量。
  - 关：不监视，只靠手动扫描。
- 全局或针对某一绑定提供 **扫描新文件**：补建尚未存在的 link；已有 link 不重复。
- 原文件被删或被移走：对应 link 标记为失效（缺失），不自动删原盘（原盘已无文件）；用户可从集合中移除该 link。
- 用户从集合移除一条「文件夹来源」的 link：视为忽略，后续扫描/监视不再自动加回（避免删了又回来）。

### 6.4 浏览与打开

- 视图：按绑定文件夹或按文件类型浏览。不提供「全部链接」「手动导入」。
- 不提供按文件名或路径搜索。
- 点击打开：用系统默认程序打开原文件（HTML 即默认浏览器）。
- 可在资源管理器中显示该文件。
- 从集合移除 = 只删 link。

### 6.5 规则（首期最小、可扩展）

- 全局文件类型列表，默认 `.html,.htm`。
- 修改类型后，新的扫描/监视按新规则生效。
- 首期不做每绑定一套不同规则；架构上规则应可在后续挂到「绑定」上。

### 6.6 数据原则

- 只存链接与绑定配置，不存文件副本。
- 配置本地持久化（如 JSON）。
- 产品崩溃或卸载，不影响原文件。

---

## 7. 首期范围（MVP）

**做：**

- 绑定文件夹、首次扫描、子目录开关
- 自动监视 / 手动扫描新文件
- 按文件夹或文件类型浏览、打开、定位、移除
- 链接失效标记
- 文件类型可配置（默认 HTML）

**不做：** 多级分组/标签、拖拽排序画布、多绑定差异化规则、安装包与开机启动、云同步。

---

## 8. 非功能需求

- Windows 10/11，本地使用，不依赖账号。
- 不扫描全盘，只处理已绑定目录。
- 监视需防抖，避免文件正在写入时误导入。
- 打开文件失败（缺失、无权限）时明确提示。
- 界面中文。
- 从集合删除时，文案必须说清「只删除链接，不删除原文件」。

---

## 9. 成功标准

1. 不打开资源管理器，能从 File Link 打开已收录的 HTML。
2. 绑定一个含多个 HTML 的文件夹后，集合里出现对应链接。
3. 向该文件夹加入新 HTML 后，自动或手动扫描能多出新链接。
4. 在 File Link 中移除链接后，原文件仍在原路径。
5. 产品不把文件复制进自己的目录。

---

## 10. 后续可能

- 链接分组、置顶、备注（更接近「工具桌面」）
- 每个绑定独立规则（扩展名、是否递归、忽略名单）
- 网页 URL、文件夹本身、程序快捷方式作为 link 类型
- 导出/导入链接清单
- 文件重命名或同盘移动后尽量找回（如 NTFS 文件 ID）
